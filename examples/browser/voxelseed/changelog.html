Dev notes

How VoxelSeed got here, newest first.

Guides and site pages

The site grows the pages you are reading: an about page explaining the generators and engines, a playing guide, and this changelog. The dashboard itself is unchanged — same seed box, same sliders, same autopilot.

WebGPU warning

When WebGPU is unavailable the page now shows a visible warning naming the problem (and dismissing it is one click) instead of failing silently, and the three.js fallback takes over rendering. Silent black canvases are the worst error message a graphics page can give.

Hand-rolled WebGPU engine

The default renderer became our own WebGPU engine — WGSL pipelines, instanced cubes from per-chunk GPU buffers, no dependencies — written because the terrain renderer is simple enough that a general engine was mostly ceremony. three.js moved to fallback duty (no WebGPU, adapter failure, or a runtime GPU error; the swap re-uploads every chunk). Force it any time with ?engine=three.

From game to dashboard

VoxelSeed became a procgen dashboard with an autopilot flythrough: the settings panel and telemetry replaced the game HUD, and the camera learned to fly itself through whatever the generator makes. This is the version most people meet today.

Biomes, then world modes

First the generator split into modes — easy plains versus complex ridged terrain — then the Biomes mode added a low-frequency biome map (desert, plains, forest, snow) and lakes below sea level. The slider set (terrain height, sea level, tree density, biome size) arrived with the modes, because a generator you cannot steer is only half an instrument.

Origins

The project started as a multiplayer voxel demo for grpc-over-datachannels: a browser-hosted gRPC game server with base64 invite links, renamed early on to VoxelSeed to stay clear of other people's trademarks. The generator outgrew the game; the multiplayer version remains in the project's git history for the curious.
